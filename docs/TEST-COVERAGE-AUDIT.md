# Brain-Dump tests and GitHub Actions audit

Audited repository: `asalaices/Brain-Dump`. HEAD: `bd40e893ecf44633bb2862c7a7fa295aca87c6b7` (0.8.6).
Evidence collected 2026-11-08 UTC. The original audit was read-only: no source, tests, workflows, records, or tracker data changed.

This document preserves that audit's complete technical findings, coverage matrix, validation outcomes, and limitations. It is a historical snapshot, not an assertion that later revisions retain or fix the findings. When documentation publication began, freshly fetched `origin/main` still matched the audited HEAD. Adding this report does not implement coverage fixes or establish new CI success. Private session bookkeeping and installation/routing details are intentionally excluded.

## Outcome

**Coverage is substantial for the Python framework, but not complete across scripts and CLI boundaries. Hosted CI was red on Windows at the audited HEAD.** Local macOS/Python 3.11.18 checks passed: 315 default-discovered tests with zero skips, 8 separately discovered bootstrap tests, and real isolated offline wheel/bootstrap acceptance. These counts are inventory/execution facts, not line or branch coverage percentages.

The highest-priority changes are to repair Windows lifecycle/path tests, make bootstrap discovery and triggers cover their dependencies, add behavioral tests for runner/controller/runtime helpers and wrappers, and enforce nonempty/non-skipped test execution. No gap was fixed in this audit.

## Prioritized findings and concrete remediation

| Priority | Finding and evidence | Recommended change / acceptance |
|---|---|---|
| P1 | **Audited-HEAD Windows CI fails**, not just missing coverage. Both Python jobs report 10 failures and 10 errors in installation/discovery cases. Run logs show Windows `os.readlink` extended-path prefix versus ordinary strings (`tests/test_skill_installer.py:101`) and launcher/source-root failures before intended assertions (`tests/test_installation.py:66-105,110-184,200-227`). | Normalize filesystem identity semantically across platforms; repair portable fixtures and backend comparisons. Preserve Windows negative installation tests and zero-skip enforcement; rerun both Windows versions rather than removing the matrix or hiding failures. Root-cause implementation remains outside this audit. |
| P1 | **Bootstrap is outside unconditional default discovery and its workflow misses implementation dependencies.** At HEAD there is no `tests/bootstrap/__init__.py`; default discovery finds 315 core cases and no `BootstrapFoundationTests`. Only B runs its eight tests. B filters omit `bootstrap.py`, `brain_bridge/**`, `pyproject.toml`, `skills/brain-dump/**`, and `MANIFEST.in` (`bootstrap-foundation.yml:4-18`), although runtime adapter imports installation (`runtime_phase.py:15,25`) and hash/profile tests depend on framework state. | Give bootstrap tests an explicit unconditional CI owner (e.g. dedicated supported-POSIX job in core workflow), or extend B filters to all dependencies. Make discovery coverage testable with expected file/case inventories. Do not blindly include POSIX-only cases on Windows: current bootstrap tests return early on `os.name=='nt'` without registering skips. |
| P1 | **Missing behavioral coverage for execution/failure boundaries** in numbered preflight/controller, shell wrappers, suite/audit tooling and shared runtimes. Positive plans bypass controller subprocesses (`controller.py:106-127`); hash/syntax/mode checks cannot establish runtime contracts. | Add focused tests in `tests/bootstrap/` or established `tests/` layout, using temporary phase registries, mocked dispatch/subprocesses, fake interpreters, synthetic command outputs and isolated telemetry. Assert exact output shapes, no-effects plans, dependency/failure stops, safe rejection and exit propagation. Wire Python/Bash cases to B/C and Node helper cases to an explicit Node-capable job/step. |
| P2 | **Runner reports success for empty/zero/skipped test execution.** `suite_runner.py:33-50` counts selected files and only child exit codes. In-memory probes reproduced `ok:true,total:0,exit:0`, zero-test and skipped-only exit 0; failed child exit 1 is propagated. Core's zero-skip policy also has no nonzero test-count guard (`tests.yml:29-31`). | Fail on empty selection and use a structured unittest child runner exposing `testsRun`/skips/errors/failures; require nonzero test execution and intended skip policy. Add behavioral self-tests covering no files, no cases, skips, assertion/import failure and invalid paths, then run them in CI. Mocked skip/zero outputs in this audit establish aggregation semantics, not actual missing current test cases. |
| P2 | **Source distribution completeness is not checked.** `MANIFEST.in:1-3` includes compatibility launcher and Python tests, but isolated build confirmed the sdist contains `tests/suite_runner.py` and bootstrap tests without `intelli_bots/bot_general.py` or `bootstrap/bootstrap.sh`; that runner cannot import its helper from the bundled source alone (`suite_runner.py:13-16`). CI builds/install-tests the checkout/wheel, not extracted sdist. | Define intended sdist capabilities and include required support assets or exclude/document unsupported bundled tooling. Add sdist-build/extract/wheel-from-sdist and supported-test checks in CI with network-free fixtures. Do not require the wheel to contain source-only `bootstrap.py`: installed CLI has its own `bootstrap` command. |
| P2 | **Several CLI actions lack dedicated native dispatch/output/error tests**, despite strong backend tests (matrix). Installed console coverage is narrower than source tests; installed operator check is only import/signature/help (`tests.yml:47-55`). | Add a table-driven command contract suite using patched backend functions and subprocess tests with synthetic repositories for representative installed flows. Assert options/defaults/confirmation, JSON/pretty parity, invalid inputs and nonzero errors. Use existing tests/workflow owners rather than duplicating frameworks. |
| P3 | **Script-contract findings are telemetry, not CI failure gates.** Workflow does not pass `--check` (`bootstrap-foundation.yml:41-42`); implementation returns 1 only with that option (`script_contract_audit.py:201,215`). Local report has 61/78 files with metadata/migration findings, including libraries/tests. | First add behavioral tests for the auditor and establish applicable script roles/migration expectations. If interface compliance is intended as a gate, adopt reviewed enforcement/baseline policy; do not label the current reporting-only step behavioral coverage or blindly fail all framework libraries. |

## Limitations

- The default audit-host `python3` was 3.8.12 and its `python3.11` shim was not selected. The initial inventory command failed at that shim; repeated inventory with the existing verified 3.11.18 environment succeeded. No dependency installation was needed to perform the audit.
- An exploratory reuse of `unittest.defaultTestLoader` for a second different start directory raised an importability error because the loader retained its first top-level directory. A fresh `TestLoader` resolved this audit-harness issue; no repository test failed.
- No local Windows/Linux execution or local Python 3.14 run; platform evidence is from actual hosted jobs and the local macOS run, not inferred from configuration. No measured line/branch coverage, full CLI fuzzing, live infrastructure acceptance, or original-audit branch-protection-required-check audit.
- Historical context consultation is not CI execution evidence, source readiness, or acceptance. This document's technical conclusions are based on the audited source, synthetic validations, and cited public workflow runs.
- Repository-local isolation and immutable-record boundaries were respected. No covering authoritative task/claim was supplied and none was invented; task acceptance is not inferred from test or Git results.
- Recommendations require behavioral tests for created/modified scripts and binaries in the established test layout, and new coverage wired into an existing or new owning Actions workflow with failures enforced. Stating that standard does not mean any recommendation was implemented.
- Private checkpoint/publication workflow state is tracked outside this public framework. This report is repository engineering documentation, not an operational Brain record or a writer authorization.
